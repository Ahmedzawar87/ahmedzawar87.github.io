How I approach quality

Four steps from an unclear requirement to a release I can stand behind.

  1. Plan by risk

    Analyze requirements, clarify gaps early and focus test effort where a failure would cost the most.

  2. Test by hand first

    Functional, exploratory, integration, cross-browser and accessibility testing to find what scripts would miss.

  3. Automate the critical flows

    Playwright and TypeScript with Page Object Model, reusable actions and stable locators.

  4. Investigate, then release

    Trace failures to selectors, network responses or logs, keep GitHub Actions runs reliable and validate the release.
